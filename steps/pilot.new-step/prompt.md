Task Pilot лежит в текущей папке. Прочитай перед работой:

Как работать:

1. Выбери id вида область.действие, которого нет среди существующих шагов; запланированный, но не реализованный шаг из steps/_planned.yaml реализовать можно. Если описание неясно или спорно, спроси владельца.
2. Шаг работает только через существующие порты. Если ему нужна интеграция, которой нет в портах, не выдумывай ее: сделай, что возможно без нее, и назови недостающее в итоге.
3. Запиши файлы шага в папку {{staging}}/steps/<id>/: step.yaml, index.ts, prompt.md для шага с агентом и тест <id>.test.ts. Тест проверяет поведение шага без внешних систем: порты и агент - подмены из steps/_test/context.ts. Сами файлы Task Pilot не меняй: папку шага в каталог перенесет конвейер после подтверждения владельца.
4. Внешние действия (Jira, git push, Bitbucket, Confluence, деплой) шаг делает только в run после подтверждения: gate publish или before и понятный preview. Публикуемые тексты проходят линтер.
5. Значения контекста, которые дают другие шаги, бери с типами из packages/step-kit/src/contracts.ts, модули других шагов не импортируй. Каждому ключу из provides шага нужен контракт: ключ из contracts.ts уже описан, а новый ключ, который кладет только этот шаг, опиши в модуле полем contracts, например contracts: { greeting: z.string() }, где z берется из step-kit.

Типы и тесты проверит конвейер на копии Task Pilot после тебя: пиши так, чтобы они прошли. В итоге верни id шага, его название, какие файлы записаны (пути от {{staging}}, например steps/<id>/index.ts) и суть шага в 1-3 предложениях, включая то, чего ему не хватает.
