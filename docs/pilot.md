# Разбор прогона, пресеты и мастер "Новый шаг"

Журнал прогона (`journalOf`, `journal.ts`) собирается из того, что уже пишется: решения "Переделать" и "Отклонить" с
замечаниями, повторы с замечанием агенту (правка `retry` с ошибкой прошлой попытки), вопросы агентов с ответами,
падения шагов (ошибка идет в данных события `step.status`; остановка владельцем и перезапуск не считаются), отказы
агенту в инструментах и круги петель. Каждая запись знает свое событие (`eventId`). Его отдают
`GET /api/runs/:id/journal`, счетчики в истории (`journal` в `GET /api/timing`) и порт `PilotPort.journal` шагам.
Карточка "Сбои и правки" (`JournalPanel`) показывает записи от свежих к старым по дням: клик по записи открывает окно
ленты на ее событии, прицел ведет к строке шага.

`pilot.retro` по журналу предлагает точечные правки промптов шагов из журнала, общих правил `steps/_shared`, правил
текстов команды (`rules.md` ее пакета) и скиллов плагина команды (`plugin/skills` пакета). Правило, которое относится
только к одной команде (ее сервисы, стенды, соглашения, слова), агент кладет в `rules.md` и скиллы пакета, а не в
промпты и правила Task Pilot. Агент пишет новые версии только в отдельную папку
рядом с доками прогона, шаг сверяет пути со списком существующих файлов, проверяет линтером только добавленные
строки (секреты, телефоны, почта, имена) и запрещает новые подстановки в промптах, а правки промптов прогоняет
тестами шагов на копии Task Pilot. Подтверждение показывает дифф каждого файла и итог проверки, упавшая проверка его
блокирует; после подтверждения код записывает файлы, если их не меняли с подготовки. Коммит правок Task Pilot и пакета
команды - по команде владельца, записанные правки действуют сразу.

Проверка правок (`checkPilot`, `pilot.ts`) копирует рабочую папку Task Pilot без зависимостей, данных и личных папок
во временную папку, подменяет файлы и запускает `tsc -p steps --noEmit` и `vitest run` по списку тестов в песочнице
оболочки. `node_modules` копии - своя папка со ссылкой на каждую запись настоящей: vitest пишет кэш и временный
конфиг внутрь `node_modules`, а песочница пускает запись только в копию. Настоящая папка не меняется.

Экран "Пресеты" (`PresetsPage`) пишет `pipelines/<id>.yaml` через `POST /api/presets`, `PUT /api/presets/:id` и
`DELETE /api/presets/:id` (`createPresetEditor`): схема, шаги без повторов и только из каталога (запланированные
тоже), выключенные только из шагов пресета и порядок шагов (`presetOrderIssues` в step-kit). Порядок проверяется по
манифестам: к каждому шагу доступны входы прогона пресета (`inputs`, по умолчанию задача и ее AC, `TASK_INPUTS`) и
`provides` шагов выше; шаг, которому нужен ключ шага ниже или ключ, которого не дает ни один шаг, - ошибка, и пресет
не сохраняется (400 со всеми ошибками), а ключ, который дает только выключенный по умолчанию шаг, - предупреждение в
ответе (`issues`). Экран проверяет черновик той же функцией: ошибки не дают нажать "Сохранить", предупреждения
видны под шагами. Умолчания настроек шагов (раздел `params` пресета: id шага, ключ и значение) редактор проверяет по
манифесту шага и статусам доски (`validPreset`): настройка только у шага пресета, только из манифеста и только из ее
вариантов. На экране их задает кнопка настроек в строке шага, а в файл пишутся только значения не по умолчанию
манифеста; они действуют во всех прогонах пресета, где настройку не выбрали в самом прогоне. У существующего файла правятся поля, комментарии остаются, каталог перечитывается сразу. Файл с
ошибкой порядка, поправленный руками, каталог оставляет загруженным и показывает ошибкой на экране "Каталог шагов", а
замечания каждого пресета отдает в `presetIssues`. На пресеты `full`, `rework` и `new-step` опирается код (`PROTECTED_PRESETS`, интерфейс
получает их в `protectedPresets` каталога): их можно править, но не удалять.

Мастер "Новый шаг" - обычный прогон со служебным ключом `PILOT-<n>` без задачи Jira: `POST /api/pilot/steps`
(`TaskService.draftStep`) заводит его с пресетом `new-step`, кладет описание в контекст `stepRequest` и запускает.
Шаг `pilot.new-step` отдает агенту описание и список шагов; агент пишет папку шага (манифест, код, промпт, тест)
в отдельную папку, может спросить владельца. Шаг проверяет id, состав папки (обязательны `step.yaml`, `index.ts` и
тест, только `.yaml`, `.ts` и `.md`) и секреты, прогоняет на копии проверку типов, тест шага и тест каталога;
подтверждение показывает все файлы и итог проверки, "Переделать" продолжает сессию агента с замечанием и выводом
упавшей проверки. После подтверждения код кладет папку в `steps/` и делает `git add`, каталог подхватывает шаг,
коммит - по команде владельца. Страница такого прогона вместо задачи показывает описание шага и не предлагает
Jira, репозиторий и стенд; наблюдатель его не трогает: снимка задачи у него нет.
