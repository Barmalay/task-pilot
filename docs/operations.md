# Запуск, проверка окружения, смоук и копии базы

Приложение и `pnpm start` запускают сервер без перезапуска при правках (`node src/main.ts`) и Vite, каждый
лидером своей группы процессов, и записывают их pid и время старта в `.data/launcher.json`: своим считается
только процесс с тем же временем старта, поэтому после перезагрузки чужой процесс с тем же pid не
останавливается. Остановка шлет SIGTERM лидеру, ждет до 15 секунд, пока сервер сам остановит агентов и сборки,
затем завершает остатки группы. Экземпляр, запущенный иначе (`pnpm dev`), запускалка видит как
`running:external` и не трогает. Приложению из Finder macOS дает урезанный PATH, поэтому запускалка ставит
впереди папку своего node, `~/.local/bin` и системный PATH из `path_helper`. Вывод процессов идет в
`.data/launcher.log`, прошлый запуск - в `launcher.prev.log`. Приложение для Dock - программа на Swift
(`launcher/TaskPilot.swift`, окно с `WKWebView`), `install.sh` компилирует ее через `xcrun swiftc`, вшивая пути к
node и `launcher.ts` и адрес интерфейса. При запуске оно вызывает `launcher.ts start` и открывает интерфейс в своем
окне, раз в 15 секунд проверяет `status` сервера, который держит, выход (Cmd+Q, "Завершить" в Dock или SIGTERM)
останавливает Task Pilot и спрашивает подтверждение, если выполняется прогон; закрытое окно приложение не
завершает. В окне открывается только интерфейс Task Pilot, остальные адреса и ссылки `target="_blank"` уходят в
браузер по умолчанию, `alert` и `confirm` страницы - в диалоги macOS. `Notification` страницы приложение заменяет
своим скриптом и показывает уведомления в Центре уведомлений, клик по уведомлению вызывает его `onclick`.
`NSAllowsLocalNetworking` в `Info.plist` разрешает окну http на 127.0.0.1. При пересборке `install.sh` снимает
работающее приложение SIGKILL, без выхода, поэтому сервер продолжает работать, а новое приложение его подхватывает. Такой сервер правки кода сам не подхватывает: после изменений в `apps/server/src`,
`step-kit`, слое компании `company/` или в `team.yaml` и `profiles/` пакета команды нужен `pnpm restart`. `pnpm dev`
запускает сервер через `apps/server/src/dev.ts`: `node --watch` перезапускает его при правке тех же папок, а пакет
команды берется так же, как при обычном запуске, из `TASK_PILOT_TEAM` или `team` личных настроек. На время перезапуска в `launcher.json` лежит метка процесса
restart, и `status` отвечает `running:ours`, поэтому приложение в Dock не принимает перезапуск за падение; при
выполняющемся прогоне перезапуск отказывается. Прогон, который ждет события (сборки, деплоя, мержа), не выполняется:
перезапуск его не прерывает, после старта его продолжит наблюдатель. Встроенная команда pnpm restart вызывает подряд скрипты `stop`,
`restart` и `start` с `npm_command=restart`: `stop` и `start` в ней ничего не делают (`skipsCommand`), иначе
сервер останавливался бы до проверки прогонов и без метки перезапуска.

Вкладка "Настройки / Служебное" (`GET /api/service`, `service.ts`) показывает сведения о самом Task Pilot. Сервер:
когда запущен, на каком коммите, и какие файлы из тех, что сервер читает только при запуске (`RESTART_AREAS`: код
сервера, `step-kit`, `api-types`, слой компании `company/`, `package.json` и настройки Vite, плюс `team.yaml` и
`profiles/` пакета команды и личные настройки), изменились
после запуска: по ним экран говорит, нужен ли перезапуск. Шаги и пресеты каталог подхватывает сам, а интерфейс -
dev-сервер Vite, он обновляется сам, поэтому их правки перезапуска не требуют. Там же предупреждение, что
`pnpm-lock.yaml` расходится с установленным lockfile pnpm (`node_modules/.pnpm/lock.yaml`), прогоны в работе и кнопка
"Перезапустить" (`POST /api/service/restart`). Она запускает `launcher.ts restart` отдельной группой процессов с
выводом в `.data/restart.log`, отказывает при выполняющемся прогоне и у сервера, которого нет в `launcher.json`
(например `pnpm dev`), а страница опрашивает сведения, пока не ответит сервер с новым временем запуска, и
перезагружается. Репозиторий Task Pilot: ветка, remote и незапушенные коммиты, последние коммиты, незакоммиченные
файлы. "Что ждет вашего решения" - гайды приемки, журналы решений (`notes.md`) и планы из `.claude/<тема>/` с
пометкой, есть ли в них вопросы; док открывается в окне (`GET /api/service/doc`, только файлы из этого списка), а
отметка "Принято" (`POST /api/service/doc/accept`, настройка `service.accepted` в базе) убирает его из списка, пока
файл не изменят. Журнал сервера - последние 200 строк `launcher.log`, `launcher.prev.log` и `restart.log` без цветов
терминала и известных токенов, ошибки и предупреждения подсвечены.

Проверка окружения (`doctor.ts`) сначала собирает факты о машине (`gatherFacts`: версии Node, pnpm, git, Maven, java
каждого JDK профилей, CLI claude и его вход, песочница, Chrome, клоны репозиториев, плагин агентов, размеры служебных
папок, копии базы), а итог по ним считает чистая функция `doctorChecks`: `fail` - Task Pilot или важная часть цикла не
заработает, `warn` - работает не все, `ok`. Встроенная команда `pnpm doctor` принадлежит самому pnpm, поэтому скрипт
называется `pnpm checkup` (`doctor-cli.ts`, код выхода 1 при `fail`), а вкладка "Настройки / Окружение" берет тот же итог из `GET /api/doctor`.
Доступ к системам проверка не проверяет, это делает экран "Интеграции": про токены она знает только, у каких
интеграций активен аккаунт Task Pilot (`activeIntegrationsIn`, база открывается только на чтение), чтобы не считать
сервер без записи в `~/.claude.json` ненастроенным. Для пакетов MCP-серверов без версии она показывает закрепленную
версию из `MCP_PACKAGES`, сам `~/.claude.json` Task Pilot не правит.

Смоук интерфейса (`smoke.ts`) поднимает демо со сценарным агентом во временной папке на своих портах
(`demo/harness.ts`, папку демо задает `TASK_PILOT_DEMO_ROOT`, поэтому открытое рядом демо он не трогает), собранный
интерфейс отдает `vite preview`, а headless Chrome по протоколу отладки открывает главные экраны навигации и прогон
DEMO-1, экраны мониторинга (фича учебной команды, дашборд и путь одной операции, найденной поиском по стадии фичи), а
кликом открывает панели (`SMOKE_PANELS`: профиль и уведомления в шапке, "Изменить по запросу" на дашборде; не
нашлась кнопка или не открылась панель - тоже ошибка), и собирает то, что считается ошибкой экрана (`pageProblems`): исключения страницы, ошибки в консоли, ответы
API с ошибкой, плашки `role="alert"` и пустой экран; обрыв потока событий при уходе со страницы и запрос
`favicon.ico` - не ошибки. Без Chrome смоук пропускается, весь проход идет около двух минут. Эталонные задачи
(`reference.ts`, `pnpm reference [DEMO-1|DEMO-2] [--script]`) ведут учебные задачи через API того же демо, но с
настоящими агентами и по промптам и скиллам рабочей папки, в том числе не закоммиченным: подтверждения принимаются
сами, на вопросы агента - заготовленный ответ эталона, итог сверяют проверки эталона (DEMO-1 - зеленая сборка,
выполненный новый тест, PR и ни одного вопроса; DEMO-2 - вопрос о делении на ноль и ответ в плане). Со `--script`
работает сценарный агент: так проверяется сам прогон эталонов, а проверки, которые умеет пройти только настоящий
агент (`agent: true`), пропускаются. Итог печатается и сохраняется в `.data/reference`. Эталоны запускает владелец
после правки промпта или скилла, до коммита; в хук они не входят, потому что тратят лимит подписки.

История дней воронок фич, накопленная скиллом feature-stats до переноса в Task Pilot, загружается разово:
`pnpm features:import [папка history]` (по умолчанию `~/.claude/skills/feature-stats/history`) читает
`history/<id>.json` каждой фичи пакета команды и пишет в базу только дни, которых там нет; скилл и его файлы не
меняются, сервер для этого останавливать не нужно.

Резервные копии базы (`backup.ts`) делает запущенный сервер: `scheduleBackups` проверяет при запуске и дальше раз в
час, и если последней копии в `.data/backups` не меньше суток, пишет новую (`VACUUM INTO` во временный файл и
переименование, поэтому оборванная копия в список не попадает) и удаляет все старше седьмой. Сбой копии сервер не
останавливает: он уходит в журнал со стеком и в общую ленту событием `backup.failed`. У демо копий нет
(`backupsDir: null`). Прогоны по сроку не удаляются: журналы агентов нужны ленте старых прогонов и разбору, лишний
прогон удаляет `deleteRun` вместе с его папками. Как вернуть базу из копии - `docs/setup.md`.
