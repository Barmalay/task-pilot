# Как запустить Task Pilot у себя

Task Pilot работает локально на Маке: сервер и интерфейс слушают только 127.0.0.1, данные лежат в папке `.data`
рядом с кодом, а во внешние системы он ходит под вашими учетными данными. Linux и Windows пока не поддерживаются:
сборки и команды агентов Task Pilot запускает только в песочнице без сети, а она сейчас есть только в macOS
(`sandbox-exec`). Песочница - порт `Sandbox` (`apps/server/src/integrations/sandbox.ts`), поэтому для другой системы
нужна своя реализация порта.

Task Pilot делится на слои. В компании, где он уже заведен, для запуска у себя файлы репозитория проекта править не
нужно, а как завести его в новой компании, рассказывает `docs/new-company.md`:

| Слой | Где | Что |
|---|---|---|
| Проект | репозиторий Task Pilot | код, шаги, пресеты, учебная команда `examples/demo` |
| Компания | `company/<id>` в репозитории Task Pilot или профили пакета команды | контуры git и Bamboo, конфиг деплоя, логи стендов и прода, адрес Jira и ее поля |
| Команда | пакет команды, свой репозиторий | `team.yaml`, репозитории и стенды команды, доска, дашборды, плагин агентов, правила текстов |
| Личное | `~/.task-pilot/profile.yaml`, `~/.claude.json`, Keychain | путь к пакету команды, логин Jira, JDK, пути, личный стиль текстов, доступ к системам |

Пакет своей команды возьмите у нее, а если команда заводит Task Pilot
впервые, начните с копии учебной команды `examples/demo`: что в пакете и как описать доску, рассказывает
`docs/team-pack.md`.

## Что поставить

Программы ниже Task Pilot проверяет сам командой `pnpm checkup`, так что начать можно и с нее: она скажет, чего не
хватает и как это поставить.

| Что | Зачем | Как поставить |
|---|---|---|
| Node 26 | сервер и интерфейс | `brew install node` |
| pnpm 10 | зависимости и команды проекта | `corepack enable`, версия возьмется из `packageManager` в `package.json` |
| git | ветки, коммиты, рабочие папки задач | `xcode-select --install` |
| JDK 21 | сборки Java-репозиториев, только под 21 | Azul Zulu 21 или Temurin 21 |
| Maven | сборки `mvn` | `brew install maven` |
| Google Chrome | QA-браузер для теста на стенде | с google.com/chrome, путь меняет `TASK_PILOT_CHROME` |
| CLI Claude Code | агенты шагов | установщик Claude Code, CLI ждется в `~/.local/bin/claude` (путь меняет `TASK_PILOT_CLAUDE`); затем `claude auth login` |

Сборки идут без сети, поэтому зависимости Maven должны уже лежать в `~/.m2`: соберите каждый Java-репозиторий один
раз обычной командой с сетью, прежде чем отдавать его Task Pilot.

## Доступ к системам

Как обычно Task Pilot берет доступ из MCP-серверов `~/.claude.json`, тех же, что у Claude Code. Имена серверов задают
профили слоев: сервер Jira и Confluence - `mcp` в `jira.yaml` (по умолчанию `atlassian`), серверы Bitbucket и Bamboo -
профили контуров (`contours/*.yaml`), сервер логов прода - `monitor.yaml`. Переменные в их `env` - как у самих серверов.
В учебном слое компании `company/example` они такие:

| Сервер | Для чего | Пакет | Переменные |
|---|---|---|---|
| `atlassian` | Jira и Confluence | `mcp-atlassian==0.23.1` через `uvx` | `JIRA_URL`, `JIRA_PERSONAL_TOKEN`, `CONFLUENCE_URL`, `CONFLUENCE_PERSONAL_TOKEN`, `TOOLSETS=all` |
| `bitbucket`, `bitbucket-core` | PR в git.cloud.example.com и git.example.com | `@nexus2520/bitbucket-mcp-server@3.0.0` через `npx -y` | `BITBUCKET_BASE_URL`, `BITBUCKET_TOKEN`, `BITBUCKET_USERNAME` |
| `bamboo-cloud`, `bamboo` | сборки и деплой в Bamboo cloud и core | `bamboo-mcp-server@1.2.0` через `npx -y` | `BAMBOO_URL`, `BAMBOO_TOKEN` |
| `elasticsearch` | логи прода для мониторинга, только чтение | `@elastic/mcp-server-elasticsearch@0.3.1` через `npx -y` | `ES_URL`, `ES_API_KEY` |

Версии пакетов закреплены: с ними Task Pilot проверен, а без версии `npx` и `uvx` берут последнюю опубликованную, и
обновление пакета может молча поменять ответы инструментов. `pnpm checkup` показывает серверы без версии или с
`@latest` и версию, на которую их поменять. Пример сервера Jira и Confluence:

```json
{
  "mcpServers": {
    "atlassian": {
      "command": "uvx",
      "args": ["mcp-atlassian==0.23.1"],
      "env": {
        "JIRA_URL": "https://jira.example.com",
        "JIRA_PERSONAL_TOKEN": "<персональный токен Jira>",
        "CONFLUENCE_URL": "<адрес Confluence>",
        "CONFLUENCE_PERSONAL_TOKEN": "<персональный токен Confluence>",
        "TOOLSETS": "all"
      }
    }
  }
}
```

Вместо серверов в `~/.claude.json` доступ можно завести на экране "Интеграции": токен проверяется запросом к самой
системе и хранится в Keychain, а сервер без записи в `~/.claude.json` Task Pilot запускает сам теми же пакетами.
Там же меняется аккаунт Jira и Claude. Доступ git для fetch и push по https дает токен Bitbucket с этого экрана или
`credential.helper` git (на Маке `osxkeychain`).

## Личные настройки

Файл `~/.task-pilot/profile.yaml` (путь меняет `TASK_PILOT_PERSONAL`) Task Pilot читает при запуске и сверяет со
схемой `personalProfileSchema`: неизвестное поле или репозиторий - ошибка запуска с именем файла, а не молчаливый
пропуск. Без пакета команды (`team` или переменная `TASK_PILOT_TEAM`) Task Pilot не запустится, без логина Jira шаг
"В работу" не назначит задачу, а без JDK не пойдут сборки Java.

```yaml
# Пакет команды: папка с team.yaml, профилями, дашбордами и плагином агентов.
team: ~/work/task-pilot-team
# Логин в Jira: на него шаги назначают задачи. С токеном Jira с экрана "Интеграции" берется владелец токена.
me: i.ivanov
# JDK 21 для сборок Java, у которых в профиле репозитория своего JDK нет.
javaHome: ~/Library/Java/JavaVirtualMachines/zulu-21.jdk/Contents/Home
# Репозиторий, который выбирается по умолчанию, вместо командного.
# defaultRepo: adapter
# Где лежат репозитории, если не там, где их ждет профиль команды (profiles/repos/*.yaml пакета).
# repos:
#   adapter: { path: ~/work/adapter, worktreesDir: ~/work/.worktrees }
# Имена, которые линтер не пропустит в публикуемые тексты, сверх списков lint.yaml слоев.
# lintNames: [Иванов]
# Личный стиль публикуемых текстов: линтер сам меняет е с точками, длинное тире и типографские кавычки.
# style: { yo: true, dash: true, quotes: true }
```

## Первый запуск

1. Получите копию репозитория Task Pilot; если у компании свой слой `company/<id>`, нужна копия с ним.
2. В папке проекта выполните `pnpm install`: он ставит зависимости и включает проверку перед коммитом.
3. Получите пакет своей команды или заведите его по образцу `examples/demo`; если Task Pilot в компании впервые,
   начните с `docs/new-company.md`.
4. Создайте `~/.task-pilot/profile.yaml` по примеру выше, с путем к пакету команды в `team`.
5. Выполните `pnpm checkup` и исправьте все, что отмечено ✗; отметка ! - предупреждение: Task Pilot запустится, но
   часть цикла работать не будет, в строке написано, какая.
6. Запустите Task Pilot: `pnpm app` соберет приложение `~/Applications/Task Pilot.app` со своим окном (нужны
   Command Line Tools: `xcode-select --install`), дальше Task Pilot запускается его иконкой. Без приложения:
   `pnpm start` в фоне и http://127.0.0.1:5177 в браузере.
7. На вкладке "Настройки / Интеграции" убедитесь, что каждая система отвечает под нужным аккаунтом; соседняя
   вкладка "Окружение" повторяет `pnpm checkup`.
8. Чтобы посмотреть цикл целиком, не трогая настоящие системы, запустите `pnpm demo:script`: демо идет на учебной
   команде и учебном репозитории с подменными Jira, Bitbucket и Bamboo и лимит подписки не тратит.

## Данные и резервные копии

В `.data` лежат база прогонов `task-pilot.db`, журналы агентов (`agent/`), файлы прогонов (`runs/`), профиль
QA-браузера (`qa-chrome/`, в нем ваши входы на стенды) и журнал запуска `launcher.log`, который при каждом старте
переезжает в `launcher.prev.log`. Папка не входит в git, а агентам читать ее нельзя.

Запущенный сервер раз в сутки кладет копию базы в `.data/backups` (первую - при запуске) и хранит последние семь.
Копия лежит на том же диске: она спасает от испорченной базы или удаленного по ошибке прогона, но не от потери
диска. Прогоны сами не удаляются, лишний удаляет кнопка "Удалить" в карточке прогона вместе с его файлами. Файлы
завершенного прогона без самого прогона чистит колонка "Кэш" на вкладке "Конвейер / История": уходят журналы агентов
и логи сборок, а время, сбои и лента остаются. Чтобы вернуть базу из копии:

1. Остановите Task Pilot: `pnpm stop`.
2. Скопируйте нужную копию на место базы: `cp .data/backups/task-pilot-<время>.db .data/task-pilot.db`.
3. Удалите журнал старой базы: `rm -f .data/task-pilot.db-wal .data/task-pilot.db-shm`.
4. Запустите Task Pilot: `pnpm start`.

Профиль QA-браузера со временем растет: `pnpm checkup` предупреждает, когда он больше гигабайта. Тогда закройте
QA-браузер и нажмите "Очистить кэш QA-браузера" в карточке "Место на диске" на вкладке "Конвейер / История":
удаляются только папки кэша профиля (`QA_CACHE_DIRS` в `cache.ts`), входы на стенды и в Kibana сохранятся.
