# Дашборды панели мониторинга

Дашборд описывает мониторинг одной задачи: какие строки лога пишет ее код, какие панели по ним строить и на какие
алерты смотреть. Он лежит в `dashboards/<id>/dashboard.yaml` пакета команды, где `<id>` совпадает с полем `id`. Панель перечитывает
файлы сама, поэтому правка руками видна на экране "Мониторинг" без перезапуска, а файл с ошибкой показывается на
обзоре с причиной и не ломает остальные дашборды. Дашборд можно написать руками или получить шагом "Дашборд задачи"
(`monitor.dashboard`): агент соберет его по коду задачи, превью покажет живые цифры с прода.

Цифры считаются по логам прода, только на чтение: кластер логов (`source`) задает `monitor.yaml` слоя компании, а
сервисы, их индексы и имена полей - `profiles/monitor.yaml` пакета команды. Поля у сервисов бывают разные:
например, текст строки Keycloak лежит в `message`, а у других сервисов - в `messagetext`. Дашборд ссылается на
сервис по id и ищет строки по фразам, поэтому эти различия ему знать не нужно.
Метрик Prometheus на панели нет, только строки лога.

## Пример

Дашборд команды:

```yaml
id: team-2609-rba
title: RBA - риск-проверка сессии при входе
description: >-
  Здоровье интеграции антифрода, покрытие и распределение score.
task: TEAM-2609            # задача, которую мониторит дашборд
epic: TEAM-2475            # необязательно: без него эпик берется из Jira
related: [TEAM-2534]       # необязательно: задачи, чьи изменения видны на дашборде
service: keycloak          # сервис панелей по умолчанию
refresh: 30s               # необязательно: 15s, 30s, 1m, 5m или off; на странице его можно поменять
headline: [checks, failopen]  # необязательно: до трех панелей с числом на карточке обзора
panels:
  - id: checks
    title: Проверки антифрода
    hint: 'Строка "Проверка антифрода RBA для state = ...: status = success"'
    type: timeseries
    match: ['Проверка антифрода RBA для state', 'status = success']
  - id: failopen
    title: Доля fail-open
    type: share
    part: { any: ['RBA: код ответа', 'RBA: ошибка вызова risk-сервиса'] }
    of: { any: ['Проверка антифрода RBA для state', 'RBA: код ответа', 'RBA: ошибка вызова risk-сервиса'] }
alerts:
  - id: no-success
    panel: checks
    when: zero
    window: 15m
```

Значение с двоеточием и пробелом после него (подсказки с цитатой строки лога) пишется в кавычках, иначе YAML его не
разберет.

## Отбор строк

У каждой панели и у частей `part` и `of` доли одинаковый отбор. Фраза - постоянная часть шаблона строки лога, без
подстановок: из `log.info("Проверка антифрода RBA для state = {}: status = {}", ...)` получаются фразы
`Проверка антифрода RBA для state` и `status = success`. Поиск идет как `match_phrase`: регистр и знаки препинания
между словами не важны.

| Поле | Что значит |
|---|---|
| `match` | все фразы должны быть в строке |
| `any` | хотя бы одна из фраз |
| `not` | ни одной из фраз |
| `level` | уровни строки, например `[WARN, ERROR]` |
| `service` | сервис панели, если он не тот, что у дашборда |

## Панели

| Тип | Что показывает | Свои поля |
|---|---|---|
| `stat` | число строк за период и изменение к прошлому периоду той же длины | - |
| `timeseries` | строки по времени; со `split` - линия на каждый срез | `split`: список `label` и отбора |
| `share` | долю строк `part` от строк `of` по времени и за период | `part`, `of` |
| `top` | самые частые значения поля или слова из текста | `by`: `level`, `logger`, `version`, `pod` или `{ extract: 'префикс ' }`; `size` |
| `numbers` | распределение числа из текста строки | `extract`: префикс перед числом; `interval`: ширина корзины |
| `lines` | свежие строки | `size`: сколько строк, до 100 |

Слово или число из текста разбирается после префикса: `extract: 'channel = '` из строки `..., channel = web, ...`
дает `web`. Такой разбор дорог для кластера, поэтому при большом числе строк он идет по случайной выборке около 2000
строк, и панель пишет, что это оценка.

У любой панели кнопка провала открывает разбивку по уровню, логгеру, версии, поду и словам, которые разбирает сама
панель, сравнение строк до и после последнего деплоя и строки лога с поиском одной попытки входа.

## Алерты

Алерт считается по панели с числом (`stat`, `timeseries` или `share`) за окно `window` (по умолчанию `15m`).

| `when` | Когда срабатывает | Поля |
|---|---|---|
| `zero` | за окно ни одной строки | - |
| `above` | величина выше порога: доля у `share`, число строк у остальных; `value: 0` у числа строк - хотя бы одна строка | `value`, `min` - только у доли: сколько строк нужно в знаменателе (по умолчанию 20, меньше - "мало данных") |
| `spike` | величина за окно выше средней за `baseline` в `factor` раз | `baseline` (по умолчанию `7d`), `factor` (3), `min` - сколько строк нужно за окно (20) |

Алерты проверяет сервер с интервалом опроса дашборда, но не чаще раза в 30 секунд; выключенный опрос выключает и
алерты. Срабатывание подсвечивает карточку на обзоре и приходит уведомлением браузера, снятие алерта видно в ленте
событий.

## Правка по запросу

Дашборд можно править и словами: кнопка "Изменить по запросу" на его странице открывает чат с агентом, который читает
этот формат и другие дашборды пакета и возвращает новый текст файла. Дифф и дашборд по черновику видны до записи,
"Применить" пишет файл, прежний текст остается версией и возвращается кнопкой в той же панели (`docs/monitor.md`).
