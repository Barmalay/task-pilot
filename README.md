# Task Pilot

Локальный конвейер полного цикла задачи: от доски Jira до мержа с подтверждением владельца
на каждом внешнем действии. Проект не знает конкретной команды: ее репозитории, стенды, доска, дашборды и скиллы
агентов лежат в пакете команды, общее для команд компании - в слое `company/<id>`, личное - в
`~/.task-pilot/profile.yaml` (`docs/team-pack.md`).

```bash
pnpm install
pnpm dev
```

Интерфейс: http://127.0.0.1:5177. Для каждодневной работы удобнее приложение с иконкой, см. ниже.
`pnpm install` включает проверку перед коммитом: хук запускает `pnpm check` и смоук интерфейса `pnpm smoke` и не
пропускает коммит с красными типами, тестами, сборкой интерфейса или ошибкой на главных экранах. После правки
промпта или скилла прогоните эталонные задачи `pnpm reference`: демо с настоящими агентами проходит DEMO-1 до PR и
DEMO-2 до плана и сверяет итог, это около $1.5 лимита подписки.
Требуются Node 26, pnpm 10, пакет команды, настроенные MCP-серверы в `~/.claude.json`
(для Jira - сервер из профиля доски, по умолчанию `atlassian`, для PR - сервер Bitbucket из профиля контура, для
сборок и деплоя - токен сервера Bamboo контура) и CLI claude под входом владельца для агентных шагов (путь в `TASK_PILOT_CLAUDE`, по умолчанию `~/.local/bin/claude`).
Вместо токенов из `~/.claude.json` и входа CLI можно завести свои на экране "Интеграции", см. ниже. Устройство
проекта и правила: `CLAUDE.md`, подробности по темам - в `docs/`, добавление шагов: `docs/adding-a-step.md`, запуск в новой компании:
`docs/new-company.md`.

Личное вынесено из репозитория в `~/.task-pilot/profile.yaml`: путь к пакету команды, логин в Jira, на который шаги
назначают задачи, и JDK 21 для сборок Java. Там же, если нужно, пути к репозиториям на своей машине, репозиторий по
умолчанию, имена, которые линтер не пропустит в публикуемые тексты, и личный стиль текстов:

```yaml
team: ~/work/task-pilot-team
me: i.ivanov
javaHome: ~/Library/Java/JavaVirtualMachines/zulu-21.jdk/Contents/Home
# defaultRepo: adapter
# repos:
#   adapter: { path: ~/work/adapter, worktreesDir: ~/work/.worktrees }
# lintNames: [Иванов]
# style: { yo: true, dash: true, quotes: true }
```

`pnpm checkup` проверяет окружение машины: Node, pnpm, git, JDK 21 и Maven, вход CLI claude, песочницу, клоны
репозиториев, пакет команды и слой компании, MCP-серверы и их версии, плагин агентов со скиллами из `team.yaml`,
Chrome для QA-браузера, резервные копии базы; то же показывает
вкладка "Настройки / Окружение". Как поднять Task Pilot на своей машине с нуля: `docs/setup.md`. Запущенный
сервер раз в сутки кладет копию базы в `.data/backups` и хранит последние семь, как вернуть базу из копии - там же.

Цикл доходит до мержа и вехи merged доски, страницы в вики и разбора прогона. Задача берется в работу (`jira.start`), готовится ветка (`git.prepare`),
агент пишет план на утверждение (`task.analyze`; если в описании задачи нет критериев приемки, план фиксирует их
своим разделом, и следующие шаги идут по ним), реализует задачу с тестами (`code.implement`), доводит сборку
до зеленой и проводит ревью (`code.verify`), а коммит, пуш, PR и перевод задачи по доске на ревью идут одним
подтверждением (`code.publish`). Затем шаг `ci.wait` ждет сборку коммита в Bamboo и, если она упала, отдает лог
агенту на разбор; `ansible.config` заводит в k8s-ansible ветку с именем ветки задачи, вносит правку конфига агентом
или по патчу из доков задачи и публикует ее; `deploy.stand` создает релиз из сборки, деплоит его на
стенд из шапки прогона и проверяет выкатку по образу пода в логах и ответу стенда. Конфиг k8s-ansible деплой
берет сам из ветки с именем ветки задачи, если она есть, и подтверждение показывает, из какой ветки он пойдет;
ветку с другим именем задает Customize Deploy, его кнопку жмет владелец. Вопросы агента и запросы
подтверждения приходят на страницу прогона: план и тексты можно вернуть на доработку с замечанием, а тексты
для публикации перед подтверждением проверяет линтер. Дальше `qa.stand` проверяет критерии приемки на стенде по
скиллу теста на стенде из плагина пакета команды (`qa.skill` в `team.yaml`) в отдельном QA-браузере, который запускает сам Task Pilot: агент управляет им только
инструментами Task Pilot, а капчу и коды из SMS просит у владельца вопросом. Скриншоты и кадры Kibana видны в
галерее на странице прогона. Если AC не прошли, `qa.fix` чинит код по отчету, кадрам и логам, и прогон заново
проходит проверку, коммит, сборку, деплой и тест только этих AC, каждое внешнее действие через подтверждение и не
больше трех кругов. `qa.publish` одним подтверждением загружает скриншоты во вложения без дублей, публикует
комментарий с таблицей AC и миниатюрами кадров, проверяет, как Jira его отрисовала, и переводит задачу по доске в
тестирование.

Сборку, деплой и мерж ждет не шаг, а фоновый наблюдатель Task Pilot: сборку, деплой и выкатку он проверяет раз в 30
секунд, PR и задачи в Jira - раз в пять минут, а после срока ожидания роняет шаг с понятной ошибкой. Ждущий прогон
переживает перезапуск сервера. На замечания ревьюеров `pr.address-review` правит код и готовит ответ на каждое, исправления
уходят через проверку, коммит и сборку, а ответы с номером коммита публикует `task.finish` отдельным подтверждением
после пуша. Когда PR смержен, `task.finish` одним подтверждением переводит задачу до вехи merged доски, рабочую папку и ветку
не трогает. Если задачу вернули или изменили описание, AC, поля или в ней новые комментарии других людей, на
странице прогона появляется плашка, а `task.rework` показывает, что поменялось, и обновляет план на утверждение.
`wiki.update` готовит страницу вики скиллом вики команды (`wiki.skill` в `team.yaml`) и показывает дифф с текущей версией, а `monitor.dashboard`
(в "Полном цикле" выключен по умолчанию) описывает дашборд задачи. Оба шага фоновые: в "Полном цикле" они стоят после
ответа на ревью и готовятся рядом с цепочкой, пока `task.finish` ждет мерж, поэтому их подтверждения приходят в то же
ожидание и время прогона не удлиняют. Подтверждений на странице прогона тогда несколько: главная кнопка открывает
первое и показывает, сколько еще, строка каждого ждущего шага открывает свое. `pilot.retro`, последний шаг цепочки,
разбирает ваши замечания на подтверждениях, ответы на вопросы и сбои прогона и предлагает правки промптов шагов
и скиллов дифом с результатом тестов; записывает их после подтверждения, коммит по вашей команде. Уведомления
браузера приходят из вкладки Task Pilot, когда нужны вы: подтверждение, вопрос агента, ответ на ваш вопрос о
прогоне, упавший шаг, конец прогона, мерж или замечания в PR, изменение задачи, алерт мониторинга. Колокольчик в
шапке хранит их историю по дням и времени со счетчиком новых, клик по уведомлению открывает его прогон, а в том же
списке уведомления браузера включаются и выключаются. Прогоны, которые ждут вашего подтверждения или ответа агенту,
шапка показывает кнопкой "Ждут вас" со списком: прогон открывается из него в один клик с любого экрана.

Репозиторий подбирается по метке repo:, компонентам и стороне задачи: у компонента с двумя репозиториями задача с
меткой frontend (без метки - с префиксом [Front]) идет в репозиторий фронтенда, с backend - в репозиторий бэкенда;
если задача репозиторий не подсказала,
прогон не запустится, пока вы его не выберете. Отметка шага - план и меняется только у шагов, которые еще не
начинались, а "Пропустить" есть у шага, на котором прогон остановился, и сразу ведет прогон дальше. На странице
прогона выполненные шаги и шаги не в плане свернуты, а сверху полоса шагов с прогнозом: до запуска - примерно
сколько займет план, в работе - процент и сколько осталось, после - факт против прогноза при запуске. Прогноз
считается по обычному времени шагов в истории и уточняется с каждым выполненным прогоном.

Пресет прогона выбирается в его карточке и меняет шаги этого же прогона: выполненные шаги
и их результаты остаются, поэтому после "Код и PR" можно переключиться на "Тест на стенде" и продолжить. Новый прогон
заводит только кнопка "Новый прогон", а лишний прогон удаляет кнопка "Удалить" после подтверждения в карточке: ветки,
рабочие папки и доки задачи при этом остаются.
Фильтр "Прогон" на доске оставляет задачи, чей прогон идет, запускался и остановился или выполнен, а у идущего
прогона на карточке полоса с процентом. На карточках задач виден исполнитель. Задачу, которой нет на доске, открывает
поле с ключом в шапке на любом экране (клавиша / ставит в него курсор). Карточку можно перетащить в другую колонку, как в Jira:
подсвечиваются статусы, куда задачу пускают ее переходы, и после броска задача сразу переводится в Jira. У задачи
может быть несколько прогонов, переключатель "Прогон" в карточке прогона открывает любой из них. Задачу, которая
меняет несколько репозиториев, ведут связанные прогоны: в каждом репозитории свой прогон (второй - кнопкой "Новый
прогон", сменив репозиторий и выбрав пресет "Связанный репозиторий"), тест на стенде в основном прогоне ждет, пока
выкатятся все, а к вехе merged задача идет, когда смержены все PR. Экран "Стенды"
показывает, что сейчас выкачено на каждый стенд: релиз и его задачу, состояние и время деплоя, образ самого нового
пода по логам и отвечает ли стенд; тот же релиз виден рядом со стендом в шапке прогона. Деплой на стенд, где стоит
релиз другой задачи, требует подтверждения с именем заменяемого релиза, а в прод Task Pilot не деплоит. Лента
прогона стоит справа сверху: в невысоком окне последние события, "Развернуть" растягивает ее на высоту экрана, а
"Вся лента" и клик по событию открывают всю историю прогона с фильтрами и поиском. Любое действие там открывается в
любой момент, в том числе после перезапуска: правка файла - диффом с номерами строк, команда агента - с выводом,
поиск - со списком файлов, подтверждение - всем, что на нем было показано, и вашим решением. Карточка
"Время прогона" показывает, сколько шел прогон и на что ушло время: агент, сборки и системы, ваши ответы агенту и
подтверждения, паузы, с лентой по шагам, а карточка "Сбои и правки" - падения шагов, ваши "Переделать" и
"Отклонить" с замечаниями, круги петель и отказы агенту. Экран "История" собирает время всех прогонов, их сбои и
правки и обычное время каждого шага, а карточка "Расход агентов" на нем - расход за день и неделю с лимитами (по
умолчанию $50 и $200 по ценам API): когда лимит исчерпан, новые агенты не запускаются, с 80% в шапке предупреждение.
Колонка "Кэш" и карточка "Место на диске" там же показывают, сколько места занимают файлы прогонов (журналы агентов
и логи сборок) и кэш QA-браузера, и чистят их: файлы - у завершенных прогонов, кэш - при закрытом QA-браузере, входы
на стенды остаются. Экран "Пресеты" создает, меняет и удаляет наборы шагов (`pipelines/*.yaml`):
порядок, какие шаги включены в новом прогоне, название и когда брать пресет. Кнопка "Новый шаг" в каталоге
открывает мастер: шаг описывается словами, Claude пишет папку шага с тестом, Task Pilot проверяет ее типами и
тестами на копии проекта, а в каталог шаг попадает после вашего подтверждения.
В шапке пять разделов: "Задачи", "Стенды", "Мониторинг", "Конвейер" с подвкладками "Каталог шагов", "Пресеты" и
"История" и "Настройки" с подвкладками "Интеграции", "Окружение" и "Служебное"; вкладка раздела открывает подвкладку, где вы были
в нем последний раз. Справа в шапке кнопка профиля: буквы вашего логина с точкой состояния аккаунтов открывают панель
справа, где собрано то, что иначе пришлось бы искать по подвкладкам: команда (пакет, слой компании, доска, статусы,
репозитории с путями на этой машине, стенды, скиллы агентов), личные настройки (логин Jira, JDK, стиль текстов),
аккаунты Jira и Claude, расход агентов, последние прогоны и сводка окружения и сервера со ссылками на подробности. Тему -
светлую, темную или как в системе - выбирает переключатель в шапке, выбор хранится в браузере. Пояснение, что на экране
и как им пользоваться, открывает значок вопроса у заголовка экрана, путь над страницей прогона ведет обратно к доске, а
кнопки и значки объясняют себя подсказкой при наведении мыши.

Экран "Мониторинг" показывает логи прода: сервисы команды из `monitor.yaml` ее пакета в кластере логов, который задает
слой компании, только на чтение. Сверху поиск попыток входа: по одному или нескольким идентификаторам (state,
correlationId, flowState, accountId, трасса), телефону, признаку, провайдеру и итогу в окне до недели. Путь попытки
(`attempt.yaml` пакета команды) собирает ее строки во всех сервисах: что показали человеку, что он нажал, какой номер и
код ввел, какие проверки прошли, какие ошибки случились, сколько шел каждый этап и чем все закончилось; телефон и код
видны только на экране. Ниже воронки фич входа (`features/<id>.yaml`): по дням с историей в базе дольше срока
хранения индекса и экран фичи с воронкой окна, исходами после шага, временем шага, автоматами и выводами, как в отчете
скилла feature-stats. Еще ниже задачи на мониторинге (`tasksJql`) по эпикам: на карточке цифры за час и сутки,
мини-график и алерты. Дашборд задачи (`dashboards/<id>/dashboard.yaml`, формат в `docs/dashboards.md`) показывает
панели за период от 15 минут до недели с отметками деплоев и опрашивается раз в 30 секунд, интервал меняется на
странице. С любой панели можно провалиться до разбивки по полю, сравнения до и после деплоя и строк лога, а из строки -
до пути попытки. Дашборд для задачи собирает кнопка "Собрать дашборд": агент по коду задачи предлагает строки лога,
панели и алерты, превью показывает живые цифры, сохраняете вы. Дашборд, фичу и правила пути можно править словами:
"Изменить по запросу" открывает чат с агентом, дифф и экран по черновику видны до записи, прошлые версии
возвращаются. Сработавший алерт подсвечивает карточку и приходит уведомлением.

Экран "Интеграции" показывает Jira, Confluence, Bitbucket и Bamboo контуров, логи прода, Kibana стендов и Claude: что
от каждой зависит, под чьим аккаунтом Task Pilot туда ходит (система сама отвечает, кто владелец токена) и откуда
взят доступ. Как обычно доступ берется из MCP-серверов `~/.claude.json` и входа CLI claude. Кнопка "Добавить токен"
заводит свой токен: он проверяется самой системой, хранится в Keychain macOS и сразу становится активным. У любой
интеграции можно завести несколько аккаунтов и переключаться между ними, в том числе обратно на доступ как обычно;
смена действует без перезапуска, а агент, который уже работает, доделывает шаг под прежним аккаунтом. Под токеном Jira
шаги назначают задачи на его владельца. Второй аккаунт Claude заводится входом через браузер (Task Pilot запускает
`claude auth login` в отдельной папке, ваш вход CLI не меняется) или токеном `claude setup-token` либо ключом API.

Контуры задает слой компании: у учебного слоя `company/example` это cloud и core, там же описано, как их подключить.
Контуру, чей Bitbucket работает по токену с экрана "Интеграции", нужен HTTP access token его git: им идут и PR, и git
fetch и push. Деплой идет на Stable и тестовые окружения Testing-*, Production, Reserve и Staging запрещены; список
стендов контура core Task Pilot читает из Bamboo по правилу в профиле контура, при запуске и раз в час.

## Приложение с иконкой

```bash
pnpm app
```

Команда собирает `~/Applications/Task Pilot.app` - приложение со своим окном, без Safari и Chrome; его можно найти
через Spotlight. Для сборки нужны Command Line Tools (компилятор Swift, `xcode-select --install`) и Chrome, которым
рисуется иконка. Клик по иконке запускает сервер и интерфейс и показывает их в окне приложения. Закрытое окно Task
Pilot не останавливает: окно вернет клик по иконке в Dock. Выход из приложения (Cmd+Q или "Завершить" в Dock)
останавливает Task Pilot; если в этот момент выполняется прогон, приложение сначала спросит. Ссылки на Jira,
Bitbucket, Kibana и стенды открываются в браузере по умолчанию, уведомления приходят в Центр уведомлений macOS:
первое включение уведомлений в списке колокольчика в шапке спросит разрешение. Чтобы иконка осталась в Dock, щелкните по ней правой
кнопкой и выберите "Параметры" и "Оставить в Dock". При первом запуске macOS может спросить доступ к папке
"Документы", где лежит проект: его нужно разрешить. Пересобрать приложение можно и на ходу: `pnpm app` завершит
старое, не останавливая сервер, и запустит новое.

Приложение запускает сервер без перезапуска при правках кода, поэтому после обновления сервера нужна команда
`pnpm restart` (или `pnpm run restart`): приложение при этом продолжает работать, а если выполняется прогон, команда
откажется. Нужен ли перезапуск, показывает вкладка "Настройки / Служебное", и перезапустить можно там же кнопкой.
Шаги
и пресеты подхватываются и без перезапуска. Если Task Pilot уже запущен иначе, например
`pnpm dev`, приложение только показывает интерфейс в окне и этот экземпляр не останавливает. То же из терминала:
`pnpm start` и `pnpm stop`, журнал запуска лежит в `.data/launcher.log`. Пути к проекту и к node вшиваются
в приложение при сборке: после переноса проекта или установки node в другую папку его нужно собрать заново той же
командой, и macOS может снова спросить доступ к папке "Документы".

## Демо-режим

```bash
pnpm demo
```

Интерфейс: http://127.0.0.1:5187. Демо идет на учебной команде `examples/demo`, а не на пакете команды из личных
настроек, и проходит тот же цикл на учебном Java-проекте, который при каждом старте
заново создается во временной папке вместе с локальным remote, а Jira, Bitbucket, Bamboo и логи стендов подменены:
задача DEMO-1 доходит до коммита, пуша и PR, в DEMO-2 агент спрашивает владельца, как делить на ноль. После пуша
подменный Bamboo собирает ветку за несколько секунд, и пресет "Тест на стенде" деплоит ее на учебный стенд demo-1
или demo-2. Агенты, сборка и подтверждения настоящие, во внешних системах ничего не меняется. Шаг конфига деплоя
в демо не настроен: у учебного проекта нет репозитория конфига деплоя. Нужны JDK 21 из личных настроек и
зависимости JUnit в `~/.m2`: сборка учебного проекта идет без сети, `mvn -o`.

```bash
pnpm demo:script
```

То же демо со сценарным агентом вместо CLI claude, лимит подписки не тратится. Он нужен для теста на стенде:
учебные стенды не настоящие, и живому агенту проверять там нечего. Реализация DEMO-1 у сценарного агента теряет
знак разности, тест на стенде это находит, доработка по тесту чинит код, и прогон с пресетом "Полный цикл" или
"Доработка" проходит второй круг до итогов в подменной Jira. Вместо скриншотов стенда агент кладет условные
картинки. Дальше подменный ревьюер оставляет в PR замечание, агент дополняет тест и отвечает, PR мержится сам,
задача доходит до вехи merged учебной доски (Done), страница вики создается в памяти, а разбор прогона предлагает правило про знак разности.
Разбор, пресеты и мастер "Новый шаг" в демо правят копию Task Pilot во временной папке, а не сам проект.
